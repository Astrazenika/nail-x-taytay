HOW TO SET UP FIREBASE FOR NAIL X TAYTAY
==========================================
(This replaces the old Google Sheets / Apps Script setup. You can ignore
and delete admin-booking-log-setup.txt now -- it's no longer used.)

Everything now lives on your own site -- no separate script.google.com
page to manage. You just need to create one free Firebase project and
paste its config into index.html.

STEP 1 — Create a Firebase project
------------------------------------
1. Go to https://console.firebase.google.com
2. Click "Add project" -> name it something like "nail-x-taytay"
3. You can turn OFF Google Analytics for this project (not needed)
4. Click "Create project"

STEP 2 — Enable Authentication (for your Admin login)
---------------------------------------------------------
1. In the left sidebar: Build -> Authentication -> Get started
2. Click the "Email/Password" provider -> toggle it ON -> Save
3. Go to the "Users" tab -> "Add user"
4. Enter the email and password YOU (the admin) will sign in with on
   the website. This is now your real login -- there's no password
   hardcoded in script.js anymore.
   (You can add more staff accounts here later the same way.)

STEP 3 — Enable Firestore Database (where bookings are stored)
-------------------------------------------------------------------
1. Left sidebar: Build -> Firestore Database -> Create database
2. Choose a location close to the Philippines (e.g. asia-southeast1)
3. Start in "Production mode" (we'll set proper rules in Step 5)

STEP 4 — Get your config and paste it into index.html
-----------------------------------------------------------
1. Click the gear icon (top left, next to "Project Overview") -> Project settings
2. Scroll to "Your apps" -> click the </> (Web) icon to register a web app
3. Give it any nickname (e.g. "Nail X Taytay Website") -> Register app
4. It will show a firebaseConfig object like:

    const firebaseConfig = {
      apiKey: "AIzaSy...",
      authDomain: "nail-x-taytay.firebaseapp.com",
      projectId: "nail-x-taytay",
      storageBucket: "nail-x-taytay.appspot.com",
      messagingSenderId: "123456789",
      appId: "1:123456789:web:abcdef123456"
    };

5. Copy that whole object.
6. Open index.html on your computer, find this block near the bottom
   (search for "YOUR_API_KEY"), and replace the placeholder values with
   your real ones:

    const firebaseConfig = {
        apiKey: "YOUR_API_KEY",
        authDomain: "YOUR_PROJECT.firebaseapp.com",
        ...
    };

7. Save index.html and re-upload it to your host.

STEP 5 — Set Firestore security rules (important!)
--------------------------------------------------------
By default Firestore blocks everything, so we need rules that:
  - let ANY visitor create a booking (so the booking form works)
  - let any visitor READ bookedSlots + blockedDates (so the calendar
    can show what's taken -- these have no name/contact in them)
  - only let a SIGNED-IN ADMIN read the full "bookings" collection
    (which has customer names/contact numbers) -- this keeps customer
    info private from random visitors

In Firebase Console: Build -> Firestore Database -> Rules tab, and
replace everything with:

    rules_version = '2';
    service cloud.firestore {
      match /databases/{database}/documents {

        // Full booking details (name, contact, notes) -- admin-only read
        match /bookings/{bookingId} {
          allow create: if true;
          allow read: if request.auth != null;
          allow update, delete: if false;
        }

        // Public, PII-free slot list -- powers the calendar for everyone
        match /bookedSlots/{slotId} {
          allow create: if true;
          allow read: if true;
          allow update, delete: if false;
        }

        // Days off -- you add these yourself in the Firestore console
        // (Firestore Database -> Data -> Start collection -> "blockedDates"
        //  -> Document ID = the date, e.g. 2026-08-20 -> any field, e.g.
        //  blocked: true) -- no one can write these from the site.
        match /blockedDates/{dateId} {
          allow read: if true;
          allow write: if false;
        }

      }
    }

Click "Publish".

STEP 6 — Test it
--------------------
1. Open your site, make a test booking start to finish.
2. In Firebase Console -> Firestore Database -> Data, you should see
   two new documents: one in "bookings" (with the full details) and
   one in "bookedSlots" (just date + time).
3. On your site, click "Admin" in the footer, sign in with the email/
   password you created in Step 2 -- you should see that test booking
   in the Booking Log table.

That's it -- no more separate script.google.com page to manage, and
your admin login is now a real account instead of a shared password.
